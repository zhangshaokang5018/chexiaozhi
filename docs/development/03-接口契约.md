## 2. `POST /api/chat` — 对话主入口 ⭐

**请求体**：
```json
{
  "user_id": "test_user_001",
  "text": "800 换机油机滤合理吗",
  "mode": "text",                // "text" | "image"
  "image_label": ""              // mode=image 时的图片标签, 如 "报价单"
}
```

> **注意（已接通）**：`routes/chat.py` 现读取 `user_id`（缺省 `test_user_001`）并取 `context.get_raw_context(user_id)`（注入 `image_label`/`mode`）传给智能体；命中且返回 `receipt_item` 时 `add_receipt_item` 沉淀。`text`/`mode`/`image_label` 仍照常读取。

**响应体**：
```json
{
  "route": {
    "agent": "maintain",         // scheduler|symptom|dtc|maintain|part
    "intent": "保养建议/报价审核",
    "confidence": 0.9
  },
  "agent": "maintain",
  "agent_meta": { "name": "保养建议 Agent", "desc": "报价/避坑指南" },
  "hit": true,                   // 智能体真实命中才为 true；异常回退和 scheduler 为 false
  "reply": {
    "title": "保养建议 / 报价审核",
    "summary": "……",
    "blocks": [
      { "type": "kv",   "label": "可能原因", "value": "……" },
      { "type": "warn", "text": "维修前建议确认项目明细、配件品牌、工时费和质保条款。" },
      { "type": "danger", "text": "🚨 高风险提醒……" }   // 高危场景
    ],
    "price_text": "参考 800-2500 元",   // 占位阶段为空字符串 ""
    "price_range": [800, 2500]          // 占位阶段为 []
  },
  "steps": [
    { "name": "意图识别", "status": "done", "detail": "保养建议/报价审核（90%）" },
    { "name": "分发至 保养建议 Agent", "status": "done" },
    { "name": "知识库检索", "status": "done" },
    { "name": "合成回复", "status": "done" }
  ],
  "elapsed_ms": 12,
  "legal_note": "所有建议仅供参考，请以当地授权维修点为准。",
  "consultation_id": "c_20260628_xxx",
  "sources": [
    { "kind": "cost", "item_id": "更换机油机滤", "title": "更换机油机滤" }
  ]
}
```

`consultation_id`、`sources` 是 2026-06-28 新增目标字段，由 A 实现：精确知识库命中和 RAG 命中都要返回真实来源；scheduler 兜底可返回空 `sources`。B 不修改 Agent/RAG 来补来源。

**`blocks[].type` 取值（当前前端类型）**：`kv`（键值对，用 `label`/`value`）｜`warn`（黄色警告，用 `text`）｜`danger`（红色高危，用 `text`）。前端还支持 `good`/`danger` 布尔标记位用于颜色。

**`steps[].status` 取值（当前前端类型）**：`done` | `doing` | `pending` | `todo`。

> ⚠️ 接入风险：`agents/maintain.py` 的真实返回里，`retrieve_node()` 未命中时会把 `steps[2].status` 写成 `miss`，`assess_node()` 报价合理时会输出 `{"type": "good", ...}`。这两个值**当前不在 `utils/request.ts` 的 TypeScript 联合类型里**，也不在上面的 chat 契约里。A-T1 接入 maintain 时必须二选一：要么后端把 `miss/good` 规范化成前端已有值，要么同步扩展前端类型与 WXML 渲染规则。

### 2.1 scheduler 意图路由规则（`agents/scheduler.py`）

| 条件 | agent | confidence | intent |
|------|-------|-----------|--------|
| `mode == "image"` | `part` | 0.95 | 图像识别/零件匹配 |
| 文本或 `image_label` 含 `[PBC]\d{4}` 故障码（正则，忽略大小写） | `dtc` | 0.92 | 故障码解读 |
| 含关键词：报价/费用/价格/多少钱/合理/贵/保养 | `maintain` | 0.9 | 保养建议/报价审核 |
| 含关键词：响/抖/顿挫/报警/灯亮/水温/机油/刹车/转向 | `symptom` | 0.86 | 症状分析 |
| 其它 | `scheduler` | 0.55 | 综合咨询/需补充信息 |

> 优先级以代码实现为准：**图片模式优先**，然后 DTC 正则、报价/保养关键词、症状关键词、兜底。因此 `mode=image` 时即便文本里带 `P0300`，也会先路由到 `part`。

### 2.2 ⚠️ 当前 vs 目标

- **当前（已打通）**：路由命中后调用对应智能体 `handle(text, context)`（`maintain/dtc/symptom/part`），用真实返回填充 `reply`/`steps`/`price_*`/`hit`/`confidence`，并把 `receipt_item` 沉淀到 context；`steps.status==miss`→`pending`、`blocks.type==good`→`kv+good:true` 已在后端 `_normalize_agent_result()` 归一。仅 `scheduler` 兜底或智能体异常时回退 `build_reply()` 占位。
- **历史**：曾由 `build_reply()` 返回写死占位，不查知识库、不做 RAG。

## 3. `POST /api/asr` — 语音转文字

**请求**：`multipart/form-data`，文件字段名 **`file`**。支持 `.mp3 / .wav / .pcm / .aac / .m4a`。前端录音规格：MP3、16000Hz、单声道、≤60s。

**响应**：
```json
{
  "ok": true,
  "text": "发动机怠速时咕噜咕噜响",
  "simulated": false,                  // true=降级占位(未配置 Key 或识别失败)
  "model": "paraformer-realtime-v2",   // 或 "fallback" / "none"
  "error": null
}
```

## 4. `GET /api/kb/<kind>` — 知识库查询

**路径参数** `kind`：`dtc` | `cost` | `symptom`
**查询参数**：`q`（关键词）、`level`（如 `high`）、`page`（默认 1）、`page_size`（默认 50，最大 100）

**响应**：
```json
{
  "kind": "dtc",
  "count": 5,
  "total": 5,
  "page": 1,
  "page_size": 50,
  "query": "P0300",
  "items": [
    {
      "id": "P0300",
      "kind": "dtc",
      "title": "P0300",
      "subtitle": "发动机缺火（随机/多缸）",
      "summary": "……",
      "detail": "……",
      "level": 3,
      "level_text": "难度 3/5",       // dtc: 难度 N/5; symptom: 高/中/低; cost: 参考价
      "level_class": "",              // dtc level>=4 或 symptom=高 时为 "danger", 否则 ""
      "stars": "★★★☆☆",
      "price_text": "零件 800-2000 元·工时 200-500 元",
      "tip": "……",
      "ask_text": "P0300 是什么意思",  // 「一键咨询」时发送给 /api/chat 的文本
      "tags": ["发动机", "缺火"],
      "raw": { /* 原始 JSON 字段 */ }
    }
  ],
  "tabs": [
    { "kind": "dtc", "label": "故障码", "count": 5 },
    { "kind": "cost", "label": "维修成本", "count": 5 },
    { "kind": "symptom", "label": "症状关联", "count": 5 }
  ]
}
```

**搜索策略**（`routes/kb.py`）：① `dtc` 类先提取 `[PBC]\d{4}` 精确匹配 → ② RAG 语义检索（距离≤0.55，取前 5）→ ③ JSON 子串匹配兜底。

## 8. 知识库 JSON Schema（`knowledge/*.json`）

### 8.2 `kb_cost.json` — 维修成本（5 条：机油/刹车片/火花塞/空调滤芯/防冻液）

```json
  "cat": "紧凑型轿车", "item": "更换机油机滤",

  "labor_low": 100, "labor_high": 200,

```

### 8.3 `kb_symptom.json` — 症状关联（5 条：异响/油压/刹车/抖动/水温）
```json
{
  "keywords": ["咕噜咕噜", "呼噜声", "异响", "水泵"],
  "fault": "水泵故障 / 冷却液循环异常 / 排气管共振",

```

> 注意 `dtc.level` 是整数(1-5)、`symptom.level` 是字符串(高/中/低)，两者不同。

## 9. 智能体返回契约（供 chat.py 接入参考）

`agents/maintain.handle(text, context) -> dict` 真实返回结构（**这是 chat.py 接入时要消费的对象**）：
```json
{
  "agent": "maintain",
  "agent_meta": { "name": "保养建议 Agent", "desc": "报价/避坑指南" },
  "intent": "保养建议/报价审核",
  "confidence": 0.9,                 // 命中 0.9 / 未命中 0.5
  "hit": true,
  "reply": { "title": "...", "summary": "...", "blocks": [...], "price_text": "...", "price_range": [low, high] },
  "steps": [ { "name": "...", "status": "done|miss", "detail": "..." } ],
  "receipt_item": {                  // 仅 hit=true 时存在, 供 context.add_receipt_item 沉淀
    "item": "更换机油机滤", "part_range": "300-500", "labor_range": "100-200", "avg": 550
  }
}
```

> 当前约定：`/api/chat` 拿到智能体返回后，用其 `reply/steps/hit/confidence` 组装第 2 节响应外形；后端会把 `steps.status=miss` 归一为前端支持的状态，并把 `blocks.type=good` 归一为 `kv + good:true`，避免前端类型发散。

## 10. 用户体系接口

> `/api/user/*` 已接入本地 **MySQL** 库 `chexiaozhi_user`，表结构见下方 §11；MySQL 不可用时返回带 `recoverable=true` 的 503，不阻断诊断主链路。

**请求体**：
```json

  "code": "wx-login-code",         // wechat 登录时传; guest 可为空
```

## 11. 用户体系数据库 Schema（MySQL）

> 库名 `chexiaozhi_user`（utf8mb4）。建库建表脚本：`car-server/sql/user_schema.sql`。`/api/user/*` 使用本库；`/api/context` 优先读取 `user_vehicle`。字段如需变更，先改本文档与该 SQL 脚本。

| 表 | 主键 | 关键字段 | 对应接口 |
|----|------|----------|----------|
| `users` | `user_id` (VARCHAR) | `login_type`、`openid`、`session_token`、`nickname`、`avatar_url`、`phone`(脱敏返回)、`profile_completed`、`created_at` | `/api/user/login`、`/api/user/profile` |
| `user_privacy` | `user_id` | `phone_authorized`、`show_vin`、`share_diagnosis_for_improvement`、`data_retention_days` | `/api/user/privacy` |
| `user_vehicle` | `user_id` | `car_model`、`vin`(脱敏)、`mileage`、`location` | `/api/user/vehicle` |
| `user_stats` | `user_id` | `consult_count`、`receipt_count`、`estimated_saved`；旧 `favorite_count` 可保留但不展示 | `/api/user/stats` |
| `user_consultations` | `consultation_id` | `user_id`、`question`、`agent`、`intent`、`reply_snapshot`(JSON)、`sources`(JSON)、`created_at` | `/api/user/consultations` |
| `user_repairs` | `receipt_id` | `user_id`、`receipt_snapshot`(JSON)、`total`、`created_at` | `/api/user/repairs` |

约定：
- `user_id` 为对外稳定主键（如 `user_10001`），由登录接口生成；chat/context/receipt 只认这个 `user_id`。
- `users.phone`、`user_vehicle.vin` 明文落库，但接口对外只返回脱敏值（`phone_masked` / VIN 前4后4），且默认不展示完整值。
- `session_token` 只允许在 `POST /api/user/login` 成功响应里返回一次，供前端写入 `cxz_session_token`；其它接口不得返回 token 明文，也不得写入日志。
- `user_privacy`/`user_vehicle`/`user_stats`/`user_consultations`/`user_repairs` 通过外键 `ON DELETE CASCADE` 关联 `users`。
- `consultation_id`、`receipt_id` 必须唯一，用于网络重试幂等；成功插入新记录时再更新 `user_stats`，重复请求不重复计数。
- 当前 Schema 为 6 张表：`users / user_privacy / user_vehicle / user_stats / user_consultations / user_repairs`。
