## 功能范围

- 首页新版入口（图 1 / 图 4 首页）：菜单进入我的、热门咨询进入真实聊天、底部输入栏为业务控件不是 Tab。
- 聊天主界面
- 用户输入
- 快捷问题
- 图片模拟输入
- Agent chip
- steps 展示
- reply blocks 展示
- price_text 展示
- legal_note 展示
- loading / error 状态
- 知识库新版列表：搜索 / 筛选 / 一键咨询仍调用 `/api/kb` 与 `/api/chat`。
- 我的页入口：无底部四项 Tab，“收藏的诊断结论”改为“咨询记录”。
- 维修记录存根页：无底部四项 Tab，展示 `/api/receipt` 真实存根。
- 咨询记录页：优先读取 `/api/user/consultations`，数据库不可用时显示本地暂存降级提示。

## 前置条件

- 小程序聊天页可打开。
- 后端服务可启动：`cd car-server && .venv/Scripts/python app.py`。
- A 主业务必须使用真实 `/api/chat`、`/api/kb`、`/api/context`、`/api/receipt`，不再以 mock 数据作为通过标准。
- B 用户体系如需完整持久化记录：安装 `requirements-user.txt`、执行 `sql/user_schema.sql`、配置 `.env` 并启动 MySQL。数据库不可用时，A 主业务仍应可用。

## A 做完后应该是什么样

- 首页能进入咨询页，咨询页不是空白页。
- 顶部能看到车辆上下文，例如车型、里程、所在地。
- 底部能输入文字，点击发送后能看到用户消息气泡。
- 快捷问题能触发一条预设问题。
- 真实 `/api/chat` 成功时能看到 Agent 名称、意图、诊断步骤、建议块、价格提示和免责声明。
- loading 时能看到等待状态。
- 网络或服务错误时能看到失败提示。
- 输入为空时不能发送。
- 发送成功后生成 `consultation_id` 并非阻塞保存咨询记录；保存失败不影响当前回复。
- 报价/故障码/症状命中后可进入维修存根页，存根含 `receipt_id` 并非阻塞保存维修记录。

以下为 MVP 之后的扩展（本期不做）：

- 知识库页三个 tab 都有搜索框和筛选入口。
- 知识库无结果时能跳转到 Agent 咨询。
- Agent 回复底部有“有帮助 / 不准确”反馈入口。
- 历史记录详情页能继续追问。

## A 自测顺序

1. 先跑自动化：`npm run typecheck` 与 `car-server/.venv/Scripts/python -m pytest`。
2. 启动 Flask 服务，打开微信开发者工具进入首页，跑 A-001 到 A-023。
3. 若本机 MySQL 已装好，再跑 DB-001 到 DB-006；若未装，记录为“数据库未就绪，A 主业务降级通过”。
4. 截图或记录首页 / 咨询 / 知识库 / 我的 / 咨询记录 / 维修存根六个页面结果。

## 数据库联调用例

| 编号 | 功能 | 输入 | 期望结果 | 自动/手动方式 |
| --- | --- | --- | --- | --- |
| DB-001 | 用户依赖安装 | `pip install -r requirements-user.txt` | PyMySQL / python-dotenv 可 import | 命令行 |
| DB-002 | 建库建表 | `mysql -u root -p < sql/user_schema.sql` | 6 张表：users/user_privacy/user_vehicle/user_stats/user_consultations/user_repairs | SQL |

| DB-004 | 咨询记录保存 | chat 成功后保存 | `user_consultations` 有 `consultation_id`，重复保存不重复计数 | 接口/SQL |
| DB-005 | 维修记录保存 | receipt 成功后保存 | `user_repairs` 有 `receipt_id`，重复保存不重复计数 | 接口/SQL |
| DB-006 | MySQL 停止降级 | 停 MySQL 后发送咨询 | `/api/chat` 仍可成功，记录保存失败不影响回复 | 手动/接口 |
