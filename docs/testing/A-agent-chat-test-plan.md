# A 角色测试计划：车况诊断与 Agent 对话链路

> **本文是「用例速查表」。** 详细的开发步骤、完成定义(DoD)、每个功能怎么自测，见
> `docs/development/A-开发与自测指南.md`（开发时以那份为主，本表用于回归核对）。
>
> **接口范围以总文档第 6 节为准。** 下表中标【后续】的用例属于 MVP 之后的扩展（知识库独立页、
> 反馈、历史继续追问等，总文档接口未定义），本期不做、不计入通过标准。

## 功能范围

- 聊天主界面
- 用户输入
- 快捷问题
- 图片模拟输入
- Agent chip
- steps 展示
- reply blocks 展示
- price_text 展示
- legal_note 展示
- loading / error 状态

## 前置条件

- 小程序聊天页可打开。
- 可使用 mock JSON，不依赖真实服务端。
- 准备 3 份 mock 数据：成功、loading、错误。

## A 做完后应该是什么样

- 首页能进入咨询页，咨询页不是空白页。
- 顶部能看到车辆上下文，例如车型、里程、所在地。
- 底部能输入文字，点击发送后能看到用户消息气泡。
- 快捷问题能触发一条预设问题。
- mock 成功时能看到 Agent 名称、意图、诊断步骤、建议块、价格提示和免责声明。
- mock loading 时能看到等待状态。
- mock 错误时能看到失败提示。
- 输入为空时不能发送。

以下为 MVP 之后的扩展（本期不做）：

- 知识库页三个 tab 都有搜索框和筛选入口。
- 知识库无结果时能跳转到 Agent 咨询。
- Agent 回复底部有“有帮助 / 不准确”反馈入口。
- 历史记录详情页能继续追问。

## A 自测顺序

1. 先断开真实服务端或保持服务端未启动，确认页面仍能用 mock 数据演示。
2. 从首页进入咨询页，跑 A-001 到 A-013。
3. 截图或记录每个用例的结果。
4. 全部通过后，再把 mock 调用切换成真实 `/api/chat`，等待联调。
