# 车小智产品原型说明

## 1. 原型基准

正式小程序原型图使用：

- `docs/prototype/chexiaozhi-miniapp-prototype.html`

功能蓝本参考：

- `C:/Users/kang/Downloads/souhou_demo_1.html`

上传的 `souhou_demo_1.html` 是桌面式演示控制台，适合展示产品逻辑、Agent 协作、知识库能力和维修闭环，但它不是最终小程序界面。正式产品原型已转译为微信小程序形态，采用多张手机屏展示：首页 / 诊断对话 / 诊断结果 / 维修记录 / 我的车辆。

视觉风格以 `souhou_demo_1.html` 为准：深色背景、蓝色渐变、深色卡片、蓝色描边、高亮状态和科技感信息面板。小程序版保留该风格，但布局改为移动端用户路径。

## 2. 产品定位

车小智是面向车主的车况翻译与维修决策助手。

核心价值：

- 把车主口语化描述、故障码、图片、报价单转换成可理解的维修判断。
- 输出故障根源、风险等级、预估费用和避坑建议。
- 通过维修记录存根形成数据闭环，为后续保养提醒、成本画像、配件撮合和换车决策提供基础。

## 3. 页面原型结构

### 3.0 小程序原型页面清单

正式小程序端原型包含 5 个核心页面：

1. 首页 / 诊断入口
   - 展示车况翻译官定位。
   - 展示当前车辆。
   - 提供语音描述、拍照问车、故障码翻译三个主入口。
   - 提供高频问题快捷入口。

2. 诊断对话页
   - 展示当前车辆上下文。
   - 支持文字、拍照、语音输入。
   - 用普通用户可理解的进度状态替代完整 Agent 面板。
   - 示例状态：识别意图、匹配知识库、生成费用与避坑建议。

3. 诊断结果详情页
   - 展示紧急程度。
   - 展示可能结论。
   - 展示建议检查顺序。
   - 展示参考费用。
   - 展示避坑建议。
   - 提供生成维修记录存根和继续追问入口。

4. 维修记录 / 闭环页
   - 展示年度维修支出。
   - 展示由 AI 诊断生成的维修记录存根。
   - 支持用户补充线下维修结果。
   - 支持报价单识别和价格合理性提示。

5. 我的车辆 / 成本画像页
   - 展示默认车辆档案。
   - VIN 脱敏展示。
   - 展示里程、所在地、上次保养。
   - 展示年度成本画像、高风险部件、下次保养建议。
   - 预留透明维修店推荐、配件价格对比、换车成本评估入口。

### 3.1 顶部产品信息区

用途：

- 明确产品名称和版本。
- 给评审快速建立产品认知。

当前界面内容：

- 标题：汽车维修翻译官 · Multi-Agent System
- 副标题：愿景，让每一位车主平等获得准确的汽车维修知识
- 版本标签：Demo v1.0 · 多智能体协作原型

小程序处理：

- 不使用桌面横幅。
- 在首页首屏用「车况翻译官」作为主心智。
- 标题和副标题压缩成移动端卡片。

### 3.2 用户上下文区

用途：

- 记录车辆基础信息，让 Agent 回答具备连续性。
- 体现 PDF 中要求的上下文记忆、车型/VIN/历史维修记录能力。

字段：

- 车型
- VIN
- 里程
- 所在地
- 清空上下文

产品规则：

- VIN 展示时应脱敏。
- 里程和车型会影响故障判断、保养周期、费用区间。
- 所在地会影响工时费和配件价格参考。

小程序处理：

- 首页和诊断页展示简化车辆卡片。
- 完整字段放在「我的车辆」页面。
- 首次进入时引导用户添加车辆，后续默认带入。

### 3.3 Agent 调度中心

用途：

- 可视化展示多 Agent 协作过程。
- 让用户理解 AI 不是直接猜答案，而是经过意图识别、专业 Agent、知识库检索后输出。

当前 Agent：

- 调度 Agent：意图路由 / 任务分发
- 症状分析 Agent：异响 / 抖动 / 报警判断
- 故障码解读 Agent：DTC 代码解析
- 零件识别 Agent：图像 / 名称匹配
- 保养建议 Agent：报价 / 避坑指南

产品规则：

- 用户输入后先进入调度 Agent。
- 根据意图分发到对应 Agent。
- Agent 处理状态需要体现「处理中」「已完成」「需补充信息」。

小程序处理：

- C 端用户不展示完整 Agent 调度中心。
- 诊断过程中改为普通进度文案：识别意图、匹配知识库、生成费用与避坑建议。
- Agent 详细路由规则进入开发文档。

### 3.4 多模态交互主区

用途：

- 承载产品主流程。
- 用户通过文字、语音、图片、快捷问题发起诊断。

当前能力入口：

- 口语症状：咕噜咕噜响
- 故障码：P0300
- 拍刹车片
- 拍机油报警
- 拍维修报价单
- 询价避坑

交互流程：

1. 用户输入问题。
2. 调度 Agent 识别意图。
3. 专业 Agent 处理。
4. 检索知识库。
5. 输出诊断建议。
6. 可生成维修记录存根。

标准输出结构：

- 故障根源
- 通俗解释
- 风险等级
- 预估费用
- 应急处理建议
- 避坑建议
- 线下维修提醒

小程序处理：

- 首页主入口为拍照问车、语音描述、故障码翻译。
- 对话页负责承接输入过程。
- 结果页卡片化展示结论、费用、避坑和强提醒。
- 高风险问题必须强提醒，例如机油灯、水温、刹车失灵、蓄电池报警。

### 3.5 Prompt 人设配置区

用途：

- 展示系统回答原则。
- 适合比赛和研发评审说明，不适合直接暴露给普通车主。

当前 Prompt 核心：

- 先检索知识库。
- 匹配时以专业、通俗、警示口吻回答。
- 必须包含故障根源、预估费用区间、避坑建议。
- 未命中知识库时建议线下专业技师协助，不能捏造。

小程序处理：

- C 端隐藏该模块。
- 后台管理端保留 Prompt 配置。
- 开发文档中需要把 Prompt 拆成系统提示词、知识库检索规则、输出格式约束、安全边界。

### 3.6 知识库区

用途：

- 展示 MVP 最小知识库。
- 体现 PDF 中的故障码映射表、维修成本基准表、常见症状关联表。

当前分类：

- 故障码
- 维修成本
- 症状关联

产品规则：

- 故障码数据用于解释 DTC。
- 成本数据用于判断报价是否合理。
- 症状数据用于把口语描述映射到故障点。

小程序处理：

- C 端不直接展示完整知识库。
- 诊断结果中展示「依据来源」和「参考范围」。
- 后台或管理端需要知识库维护页面。

### 3.7 维修记录存根

用途：

- 模拟维修闭环。
- 把一次 AI 咨询转成可沉淀的数据记录。

当前内容：

- 客户车辆
- VIN
- 服务时间
- 服务门店
- 维修项目明细
- 预估合计
- 保存记录

产品价值：

- 支撑用户历史维修记录。
- 支撑后续成本画像。
- 支撑配件需求预测。
- 支撑换车决策和商机识别。

小程序处理：

- 诊断结果页增加「生成维修记录」按钮。
- 完成维修后用户可补充实际价格、门店、照片和发票。
- 形成「车辆档案」和「年度维修成本报告」。

## 5. 当前原型需要调整的点

保留：

- 三栏结构适合演示产品逻辑。
- Agent 调度可视化清晰。
- 多模态快捷入口覆盖 MVP。
- 知识库三分类与 PDF 要求一致。
- 维修核销单很好地体现闭环。

需要产品化调整：

- 桌面三栏需要拆成移动端页面流。
- 普通用户界面应弱化 Prompt、知识库、Agent 技术细节。
- VIN 需要默认脱敏。
- 输出结果需要更结构化，避免长聊天气泡造成阅读压力。
- 高风险报警需要更强的视觉提示。
- 增加「报价单识别后对比市场价」的结果卡。
- 增加「本建议仅供参考」合规提示的固定位置。
